# 阶段 7：方案生成与风险分级（续）

> （本卷为阶段 7–12 及附录；已融入 13 类智能体映射，详见各阶段 .N 小节与附录 B/C/D。）

> **本版完善说明**：本方案在原分阶段工程骨架基础上，融入"人工智能+制造""人工智能+软件"两大框架下
> 需构建的 **13 类智能体（装备侧 A1–A5、软件侧 B1–B5、行业专用 C1–C3）**，把原来抽象的"7 个通用 Agent"
> 升级为与具体业务智能体逐一对齐的可落地规格，并在各阶段补齐"本阶段服务于哪些智能体、智能体在此阶段如何落位"的映射。

## 建设目标：两大框架与 13 类智能体（贯穿全篇）

系统不改变现有主营业务，而是在两大框架下把现有装备与服务升级为"装备级大模型服务 + 装备级智能体服务"：

- **人工智能+制造**（装备侧）：让柔性装配平台、CTU 库房、AGV、智能/检测工位具备"感知—校验—执行—上报—记录"闭环，构建 **A1 工位装配、A2 物料配送、A3 质量追溯、A4 产线调度、A5 实训教学** 共 5 类装备侧智能体。
- **人工智能+软件**（软件侧）：把 MES/WMS/WCS/工位软件/追溯系统升级为可被智能调用的工业软件底座，构建 **B1 装配智能体入口、B2 物流智能体服务、B3 智能管控大模型服务、B4 质量追溯智能体服务、B5 实训智能体服务** 共 5 类。
- **行业专用**（两框架融合）：沉淀可复用行业工艺与追溯规则，构建 **C1 轨道装备装配、C2 航空装配、C3 快速换型** 共 3 类。

合计 13 类。下方各阶段在保留通用工程纪律的同时，标注与这 13 类智能体的对应关系。



## 7.4 方案校验清单（续）

- 是否明确标注数据缺口与不确定项
- 是否给出人工确认的触发原因
- 是否对高风险动作给出责任人建议与超时策略
- 是否避免输出具体控制指令（仅输出建议与风险）

校验不通过的处理：

| 校验失败项 | 处理 |
| --- | --- |
| 结论无证据 | 删除该结论，或降级为"待验证假设" |
| 动作无前置条件 | 补齐前置条件，无法补齐则置 executable=false |
| 出现禁止动作 | 直接拦截，记录审计，转人工 |
| 置信度与证据不匹配 | 下调置信度，并升级风险等级 |
| 知识过期 | 保留引用但标注"依据可能过期"，禁止自动执行 |

## 7.5 置信度计算（保守策略）

```
综合置信度 = min(
    各相关 Agent 置信度,
    证据完整度评分,
    知识适用性评分
)

证据完整度 = 已获取关键数据项 / 该场景必需数据项
知识适用性 = 命中且未过期且设备/工序匹配 的文档权重
```

不使用平均值，避免"一个强证据掩盖多个缺口"。

## 7.7 验收标准

- 任意方案中，高风险动作 100% 带 requires_human_confirm=true
- 方案中每条结论均可回溯到证据或知识引用
- 证据不足时系统输出"不确定 + 转人工"，而非强行给方案
- 风险升级规则可通过测试用例覆盖（数据缺失、知识过期、结论冲突三类）

## 7.8 风险分级与 13 类智能体的对应关系

阶段 7 生成的每条 `ProposedAction`，其 `risk_level` 与 `requires_human_confirm` 必须与该动作归属智能体在 5.8 表中标注的"关键动作人工确认"一致。落位规则：

| 智能体动作 | 默认风险 | requires_human_confirm | 说明 |
|---|---|---|---|
| A1/B1 装配引导、E-SOP 记录、码绑履历 | 中 | 否 | 仅记录态可自动，触发设备停机复位则升为高 |
| A2/B2 备料补料建议、路径/冻结变更 | 低 / 高 | 建议否 / 变更是 | 配送执行建议可自动，路径重算下发与批次冻结需确认 |
| A3/B4 追溯定位、异常批次识别 | 中 | 否 | 定位可自动，隔离/复检/返工/停线等处置动作升为高 |
| A4 动态调度建议 | 中-高 | 下发是 | 仅生成建议，调度实际下发需确认 |
| B3 异常诊断、报表、追溯分析 | 低-中 | 否 | 分析与报表自动；涉及停机/改参数的控制建议一律转确认 |
| C1/C2/C3 行业规则增强（换型/审计/远程运维） | 中-高 | 是 | 换型下发、审计处置、远程运维经验固化动作均需确认 |
| A5/B5 实训任务发布与评分 | 低 | 否 | 与生产异常闭环解耦，不在事件主链路强制确认 |

要点：上述对应关系保证——任一智能体的"是否需人工确认"在方案层即被锁定，不允许在阶段 8 执行时被绕过；行业专用 C1–C3 的风险动作沿用其所复用通用智能体（A1/A3/B4 等）的人工确认边界，不单独放宽。


# 阶段 8：执行与人工确认闭环

## 8.1 目标

让低风险动作真正闭环，中风险动作形成待办，高风险动作受控确认，全过程可回滚。

## 8.2 执行分流

| 风险 | 执行方式 | 典型动作 |
| --- | --- | --- |
| 低 | 自动执行 | 补充查询、记录诊断结果 |
| 中 | 自动执行但生成待办 | 工单草稿、通知责任人、处置建议单 |
| 高 | 生成确认请求，人工审批后执行 | 停机、改参数、冻结批次、改工单状态 |

## 8.3 执行前置再校验（不可跳过）

1. 权限再校验（以当前操作者为准，不沿用生成方案时的角色）
2. 参数再校验（重新查设备/工单/批次当前状态）
3. 幂等再校验（同一 incident_id + action_id 只执行一次）
4. 前置条件再校验（如"设备处于运行态"是否仍成立）
5. 审计写入执行意图

任一不通过 → 不执行，转为"需人工处理"并说明原因。

## 8.4 人工确认请求结构

```python
class ConfirmRequest(BaseModel):
    confirm_id: str
    incident_id: str
    plan_id: str
    action_id: str
    action_title: str
    action_detail: str
    tool_name: str
    tool_args: dict

    risks: list[str]
    rollback_hint: str
    required_roles: list[str]
    assignee: str | None = None
    created_at: datetime
    expire_at: datetime
    status: Literal["pending", "approved", "rejected", "expired", "executed", "failed"]
    decision_by: str | None = None
    decision_at: datetime | None = None
    decision_note: str | None = None
```

## 8.5 确认超时策略

- 超时未确认 → 状态置 expired，不自动执行
- 通知升级（责任人 → 上级）
- 记录为"未处置"，进入待办看板
- 严禁"超时默认同意"

class ActionExecution(BaseModel):

## 8.7 回滚设计

- 每个可执行动作在生成时必须给出回滚方式，无法回滚的动作不得自动执行
- 回滚同样走权限校验 + 审计
- 回滚失败 → 立即升级人工，标记事件为"需紧急处理"

## 8.8 异常处理

| 异常 | 处理 |
| --- | --- |
| 执行失败 | 记录错误码，尝试一次安全重试（仅幂等且只读/可重复写） |
| 部分成功 | 标记 partial，列出已完成与未完成项，转人工 |
| 状态已变化 | 中止执行，重新分析或转人工 |
| 确认人权限不足 | 拒绝并重新指派 |

## 8.9 验收标准

- 高风险动作无确认记录时执行次数为 0
- 确认超时不会自动执行
- 每个已执行动作都有执行记录与回滚提示
- 重复触发同一事件不产生重复工单/重复通知

# 阶段 9：审计、可观测与评估

## 9.1 目标

让系统"能被审查、能被复盘、能被持续改进"。

## 9.2 审计记录内容

```python
class AuditRecord(BaseModel):
    audit_id: str
    trace_id: str
    incident_id: str | None
    actor: str
    roles: list[str]
    action: str
    target: str | None
    input_snapshot: dict
    output_snapshot: dict
    risk_level: str | None
    decision: Literal["allowed", "denied", "confirmed", "rejected", "executed", "rolled_back"]
    reason: str | None
    created_at: datetime
```

审计必须覆盖：事件接入、治理决策、Agent 调用、工具调用、知识命中、方案生成、风险判定、确认审批、执行与回滚。

## 9.3 可观测指标

| 类别 | 指标 |
| --- | --- |
| 事件 | 事件量、重复率、聚合率、死信量 |
| 时延 | 事件到方案生成时长、到执行时长 |
| 智能体 | 各 Agent 成功率、结构合规率、平均置信度 |
| 检索 | 知识命中率、过期命中率、无命中转人工率 |
| 执行 | 自动执行数、确认数、拒绝数、失败率、回滚率 |
| 质量 | 误判率、漏判率、人工推翻率 |
| 成本 | 单事件模型调用次数与开销 |

## 9.4 评估集建设

- 从历史事件中抽取 100–300 条，按场景分层
- 每条标注：正确问题判定、正确原因、正确处置、应否人工确认
- 分为开发集、验证集、保留测试集，避免调参污染

## 9.5 评估方式

- 判定类：准确率、召回率、误报率
- 方案类：证据支撑率、动作合规率、人工采纳率
- 安全类：高风险动作违规执行次数（目标恒为 0）
- 回归机制：每次改提示词、改工具、改模型，跑完整评估集

## 9.6 验收标准

- 任一历史事件可完整回放：事件 → 治理 → Agent → 知识 → 方案 → 执行
- 关键指标有基线与目标值，且可按月对比
- 高风险违规执行次数为 0

# 阶段 10：集成与上线

## 10.1 目标

在不影响现有业务系统的前提下，逐步接入并放量。

## 10.2 集成方式

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| 消息订阅 | 有消息能力的系统 | 首选，低侵入 |
| 只读视图/只读账号 | 数据库直连场景 | 严禁写权限 |
| API 适配 | 有开放接口的系统 | 统一走 Adapter |
| 定时轮询 | 老旧系统 | 需做变更比对与去重 |
| 人工录入 | 无系统记录的场景 | 作为补充事件源 |

## 10.3 上线阶段

阶段 A：影子模式（只读）

- 系统接收事件、生成方案，但不执行任何写操作
- 与人工实际处置结果对比，统计误判与漏判

阶段 B：低风险自动

- 开放查询、记录诊断、生成工单草稿、发送通知
- 保留全量审计与人工抽查

阶段 C：中风险闭环

- 待办确认流上线，责任人处理闭环
- 统计采纳率与推翻率

阶段 D：高风险受控

- 仅对少数明确、可回滚、有权限约束的动作开放审批后执行
- 每次执行强制双人确认或上级确认（按现场制度）

## 10.4 灰度与回退

- 按产线 / 设备类型 / 事件类型灰度
- 提供总开关：一键停止自动执行，退回纯提示模式
- 提供场景开关：单场景可独立停用
- 模型或知识异常时自动降级为规则 + 人工

## 10.5 验收标准

- 影子模式期间不影响任何业务系统写入
- 灰度期间业务系统无因本系统导致的故障
- 回退开关在分钟内生效并验证过

# 阶段 11：运维、迭代与治理

## 11.1 日常运维

- 死信队列每日清理与归因
- 知识库版本与生效期巡检
- 工具接口可用性与超时监控
- 模型成本与调用量监控
- 确认待办积压监控

## 11.2 知识治理

- 文档变更触发重新索引
- 过期文档自动降权并提示
- 人工推翻的结论回流为案例，经审核后入库
- 知识责任人制度，避免"无人维护的 SOP"

## 11.3 提示词与模型迭代

- 提示词版本化管理，变更需过评估集
- 模型更换需做同集对比，不直接上线
- 保留旧版本可快速回退

## 11.4 治理机制

- 建立变更评审：新增工具、新增可执行动作、调整风险规则必须评审
- 建立红线清单年度复核
- 建立事件复盘机制：误判、漏判、违规拦截均复盘

## 11.5 验收标准

- 知识过期率、待办积压率、死信量有明确阈值与告警
- 提示词/模型/工具变更均有评估记录
- 每季度输出一次误判率与采纳率报告

# 阶段 12：第一版最小可用范围（建议）

## 12.1 只做一件事

设备异常诊断 + 维护建议 + 工单草稿，其余场景后续扩展。

## 12.2 第一版包含

- 单一设备系统事件接入
- 事件标准化 + 去重 + 聚合
- 设备诊断 Agent + 维护建议 Agent + 知识检索 Agent
- 主调度 LangGraph 流程
- 只读工具 + 工单草稿 + 通知
- 风险分级与人工确认（仅确认，不执行控制）
- 审计与回放
- 评估集 ≥ 50 条

## 12.3 第一版明确不做

- 不执行停机、启机、参数修改
- 不修改工单状态、不冻结批次
- 不做多产线全场景
- 不做自由协作的多智能体
- 不做无人工确认的写操作

## 12.4 第一版成功标准

- 事件到方案生成时延满足现场要求
- 诊断结论人工采纳率达到约定阈值
- 高风险违规执行次数为 0
- 全链路可回放

## 12.5 第一版收敛到哪些智能体

把 12.1 的"设备异常诊断 + 维护建议 + 工单草稿"落到 5.8 编号上，第一版只做：

- **B3 智能管控大模型服务**（异常诊断、维护建议、报表生成的主入口）
- **A3 质量追溯智能体 + B4 质量追溯智能体服务**（取证与追溯定位）
- 关联调用 **A1 工位装配 / B1 装配入口** 只读取证（不触发其写动作）

第一版明确不做（对应 5.8 边界）：A2/B2 配送路径下发、A4/B3 停机启机改参数、批次冻结与工单状态变更，以及 C1–C3 行业专用与 A5/B5 实训类。所有上述高风险动作按阶段 8 仅生成建议与待确认，不执行。
